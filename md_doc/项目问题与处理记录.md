## 1. 文档说明

本文记录 AniNexus 自当前可追溯开发阶段以来出现的问题、根因、处理结果与遗留风险。

状态定义：

- **已解决**：代码已修复，并至少通过针对性测试或构建验证。
- **部分解决**：基础能力已完成，但尚未达到最终产品目标。
- **待处理**：问题已经确认，但当前没有完成实现。
- **环境问题**：主要由本机、沙箱、文件权限或工具链导致，不属于线上业务逻辑。
- **设计风险**：尚未造成已确认事故，但现有实现继续扩展时可能产生错误。

“所有问题”以当前能够找到证据的记录为准；早期未进入 Git、文档或任务记录的问题无法追溯，不在本文中臆测补写。

## 3. 基础架构与工程质量问题

### ENG-001：旧 `search_manga` 数据库与新应用耦合

- **现象**：新环境需要依赖旧数据库才能获得目录数据，部署和数据权限边界不清晰。
- **根因**：公共目录没有独立的标准化导入格式。
- **处理**：建立新的 `aninexus` 数据库模型、只读旧库导入器和可发布的 gzip JSON Lines 公共目录包。
- **状态**：**已解决**。
- **遗留**：正式公开数据包仍需确认上游数据与图片的再分发许可。

### ENG-002：前端存在大量静态检查问题

- **现象**：初次全面检查发现 158 个 ESLint 问题，包括未使用导入、宽泛 `any`、Hook 依赖和组件属性类型不一致。
- **根因**：早期演示代码快速迭代，缺少持续的 lint/typecheck 收口。
- **处理**：清理未使用代码、补齐类型、修正 Hook 与组件接口。
- **状态**：**已解决**；当前 ESLint 和 TypeScript 检查通过。

### ENG-003：Next.js 最终生产构建曾被中断

- **现象**：登录/CAPTCHA 工作完成后，最终生产构建启动但未得到完整结果。
- **根因**：任务执行被中断，不能把“已开始构建”当成“构建成功”。
- **处理**：后续重新执行完整构建并验证。
- **状态**：**已解决**。

### ENG-004：Windows 沙箱中 Next.js 构建出现 `spawn EPERM`

- **现象**：代码编译成功后，Next.js 在创建页面数据工作进程时失败。
- **根因**：Windows 沙箱阻止子进程创建，不是 TypeScript 或页面代码错误。
- **处理**：在获准的非沙箱环境重跑同一构建，生产构建完成。
- **状态**：**环境问题，已绕过并验证**。

### ENG-005：Docker MySQL 端口冲突

- **现象**：启动 AniNexus MySQL 容器时提示 `3306` 已被占用。
- **根因**：本机已有名为 `mysql` 的容器监听 `3306/33060`。
- **处理**：没有停止或覆盖现有容器；改为连接已有数据库，并删除本轮创建失败的 `aninexus-mysql-1` 容器。
- **状态**：**已解决**。
- **建议**：后续若必须使用 Compose 自带 MySQL，显式设置不同的 `MYSQL_PORT`。

### ENG-006：Git 工作区存在大量未提交改动

- **现象**：前后端、文档、脚本和静态资源同时处于修改或未跟踪状态，变更范围较大。
- **风险**：难以按功能回滚，代码审查噪声高，也容易把用户已有改动误归入单次任务。
- **状态**：**待处理**。
- **建议**：按“认证、首页、Bangumi 迁移、日历、文档”拆分提交，并在提交前分别运行验证。

## 4. 登录、认证与用户数据问题

### AUTH-001：项目缺少完整的站内用户名/密码认证

- **现象**：个人接口和用户界面缺少一致的注册、登录、会话和退出流程。
- **处理**：实现 PBKDF2-SHA256 密码哈希、随机图片验证码、30 天不透明会话、HttpOnly/SameSite=Lax Cookie，以及注册、登录、`me`、退出接口。
- **状态**：**已解决**。

### AUTH-002：验证码可能被重复使用

- **风险**：如果验证码失败后仍能继续使用，会削弱验证码的一次性约束。
- **处理**：验证码无论成功或失败都按一次性方式消费，并增加测试。
- **状态**：**已解决**。

### AUTH-003：移动端验证码图片裁切

- **现象**：移动端登录/注册界面中验证码图片比例不正确，内容可能被裁掉。
- **根因**：图片容器尺寸与原始图片比例不一致。
- **处理**：保留验证码原始宽高比，并进行移动端视觉复核。
- **状态**：**已解决**。

### AUTH-004：个人 Bangumi Token 方案不适合多用户部署

- **现象**：当前主要使用服务端个人 Access Token；有效期、用户隔离和泄露影响范围均不适合公开多用户服务。
- **处理进度**：已完成 OAuth 申请材料和安全边界设计。
- **状态**：**待处理**；Authorization Code、Refresh Token、按用户加密存储和解绑流程尚未完整落地。

## 5. 首页、搜索与目录数据问题

### CAT-001：首页到底使用 MAL 还是 Bangumi 缺少明确决策

- **现象**：首页数据来源、评分来源和迁移顺序长期不明确。
- **决策**：首页最终使用 **Bangumi 主数据 + MAL 补充字段**；Web 请求始终读取 AniNexus 本地数据库，不直接依赖上游。
- **状态**：**部分解决**；接口契约和 feature flag 已完成，数据库数据融合与正式切换尚未完成。

### CAT-002：首页无法说明评分来源和数据新鲜度

- **现象**：同一个分数无法判断来自 MAL 还是 Bangumi，也无法判断数据是否过期。
- **处理**：目录接口增加 `primary_source`、`score_source`、`data_updated_at`、`is_stale`，前端显示来源和“待更新”。
- **状态**：**已解决**。

### CAT-003：搜索关键词中的 `%` 和 `_` 被当成 SQL 通配符

- **现象**：用户搜索字面 `%` 或 `_` 时会意外扩大匹配范围。
- **根因**：`LIKE` 查询没有转义 SQL 通配符。
- **处理**：统一转义反斜杠、`%` 和 `_`。
- **状态**：**已解决**。

### CAT-004：NSFW 作品可能进入默认首页结果

- **现象**：目录筛选没有默认排除 Bangumi `nsfw=true` 数据。
- **处理**：默认隐藏 NSFW，只有显式设置 `include_nsfw` 才返回。
- **状态**：**已解决**。

### CAT-005：Bangumi Archive 不能直接作为 AniNexus 公共目录使用

- **现象**：原始归档约 665 万行、9 个文件，字段和类型不符合现有数据库。
- **处理**：实现流式校验与转换器，支持类型筛选、批处理、NSFW 排除、dry-run 和公共目录包输出。
- **状态**：**部分解决**；当前重点覆盖作品，尚未覆盖全部关系数据。

### CAT-006：Bangumi Archive 本身没有封面 URL

- **现象**：归档作品数据无法直接满足首页和详情页封面展示。
- **处理方案**：Archive 作为历史基线；当季、热门、收藏和最近访问作品通过 Bangumi 接口后台补齐封面，MAL 封面作为回退。
- **状态**：**待处理**；完整封面预热和 TTL 缓存任务尚未实现。

### CAT-007：Bangumi 与 MAL 直接导入会产生重复 canonical 作品

- **现象**：现有作品唯一键是 `(source, source_id, subject_type)`；同一动画的 MAL 与 Bangumi ID 不同，直接导入会形成两条作品。
- **处理**：新增 `subject_external_ids`，实现只读匹配计划和受保护的映射 apply 步骤。
- **结果**：28,316 条公开动画中，8,557 条已有 Bangumi 映射。
- **状态**：**部分解决**；映射已建立，但 canonical 字段融合和新增作品导入尚未完成。

### CAT-008：MAL 动画和漫画 ID 命名空间可能碰撞

- **现象**：仅使用 `(provider, external_id)` 作为外部身份唯一键，无法区分相同数字 ID 的 MAL 动画与漫画。
- **处理**：唯一键调整为 `(provider, external_id, subject_type)`，并迁移现有表结构。
- **状态**：**已解决**。

### CAT-009：标题和日期完全一致仍可能对应正篇、特典或短片

- **现象**：真实匹配中有 11 条 Bangumi 动画同时命中多个 MAL 候选。
- **典型原因**：正篇与 Specials、短片、第 0 集拥有相同标题和首播日期。
- **处理**：唯一候选才允许 `auto_link`；多候选进入 `review`，不自动合并。
- **状态**：**待人工复核**。

### CAT-010：19,748 条 Bangumi 动画尚未进入 canonical 目录

- **现象**：真实匹配计划将这些记录判断为 `new_subject`。
- **状态**：**待处理**。
- **前置条件**：完成映射感知的写入、字段融合、备份和回滚机制，不能直接使用普通来源 upsert。

### CAT-011：全部 Archive 数据缺少数据库表

- **现象**：归档包含章节、人物、角色、作品—人物、作品—角色、人物—角色和作品关系，但当前数据库没有对应规范化表。
- **影响**：推荐、Staff、声优、前后作和改编关系只能使用不完整的 JSON/文本数据。
- **状态**：**待处理**。

### CAT-012：没有正式的数据库迁移机制

- **现象**：当前主要依赖 SQLAlchemy `create_all`；它不能可靠修改已经存在的表。
- **影响**：字段、唯一键和索引调整需要临时 SQL，生产升级不可审计、不可回滚。
- **状态**：**待处理**。
- **建议**：引入 Alembic，并为已有数据库建立基线 revision。

### CAT-013：尚未实现官方快照的增量同步

- **现象**：目前可以转换和匹配单份 Archive，但不能自动比较新旧快照。
- **目标**：按稳定 ID 和内容哈希区分 `new`、`changed`、`unchanged`、`missing`、`conflict`。
- **状态**：**待处理**。

### CAT-014：当前内容哈希可能受本地文件时间影响

- **现象**：Archive 转换的 `source_updated_at` 来自文件修改时间，而外部 ID 哈希包含整个转换记录。
- **风险**：相同快照重新下载后，文件时间变化可能让所有记录被误判为已修改。
- **状态**：**设计风险，待处理**。
- **建议**：稳定内容哈希排除下载时间；快照时间、抓取时间和导入时间分列保存。

### CAT-015：空值可能覆盖已有高质量字段

- **现象**：通用 upsert 会更新输入记录提供的字段；如果上游字段为空，可能覆盖 API 或 MAL 已补齐的数据。
- **状态**：**设计风险，待处理**。
- **建议**：把字段融合规则集中到单一模块，按来源优先级执行“非空覆盖”，并记录字段级来源。

### CAT-016：Archive 常量尚未版本化

- **现象**：`platform`、`position`、`relation_type` 等为数字常量，当前没有固定 Bangumi common 版本。
- **影响**：未来上游常量变化可能导致历史数据解释不一致。
- **状态**：**待处理**。

### CAT-017：上游数据和图片再分发许可未确认

- **现象**：技术上可以生成公共目录包，但是否能随 Release 公开分发仍需确认许可和署名要求。
- **状态**：**待确认**。

## 6. 追番日历问题

### CAL-001：“浏览本周新番”请求成功后页面不可用

- **现象**：公开日历与状态接口均返回 HTTP 200，但点击按钮后新番卡片不能正常使用。
- **根因**：Bangumi 日历返回 555 个 `http://lain.bgm.tv/...` 封面，而 Next Image 只允许 `https://lain.bgm.tv`，数据进入组件后触发图片源协议错误。
- **处理**：后端统一把可信 Bangumi 图片源升级为 HTTPS；前端增加第二层防御性规范化。
- **验证**：修复后日历封面统计为 HTTP 0、HTTPS 555，并新增回归测试。
- **状态**：**已解决**。

### CAL-002：连接状态失败会阻断公开日历

- **现象**：按钮使用 `Promise.all` 同时等待公开日历和个人连接状态；任一请求失败都会让整个操作失败。
- **根因**：无需 Token 的公开数据与可选个人状态被错误地绑定为同一成功条件。
- **处理**：改为 `Promise.allSettled`；只有日历失败才阻断展示，状态失败不影响公开日历。
- **状态**：**已解决**。

### CAL-003：公开日历没有真实播出时刻

- **现象**：Bangumi `/calendar` 主要返回日期和星期，前端当前从 18:00 开始按 20 分钟间隔生成展示时间。
- **影响**：时间轴位置是布局占位，不一定等于真实电视/流媒体播出时间。
- **状态**：**已知限制，待处理**。
- **建议**：从结构化 infobox、章节数据或可信的定向刷新接口补全真实播出时间，并标记时间来源。

### CAL-004：公开日历仍在每次操作时直连上游

- **现象**：当前后端 `/bangumi/calendar` 直接请求 Bangumi，没有实现文档中规划的共享缓存。
- **影响**：上游超时或限流会影响按钮；访问量增加时会放大请求。
- **状态**：**待处理**。
- **建议**：增加全站共享 TTL 缓存和 stale-while-revalidate 降级。

### CAL-005：导入本周新番后封面显示异常

- **现象**：修正 HTTP/HTTPS 协议后，日历数据可以载入，但封面仍可能空白或显示加载异常。
- **根因**：`next/image` 默认由 Next.js 服务端抓取远程图片；当前运行环境访问 `lain.bgm.tv` 失败，图片优化请求返回 `504 Gateway Timeout`。
- **处理**：Bangumi 封面改为浏览器直接加载，不再经过 Next 图片优化器；同时增加 `onError` 回退，远程图片不可用时显示现有分类占位图，避免破图。
- **状态**：**已解决**。

### CAL-006：当前时间红线横跨整周

- **现象**：“浏览本周新番”时间网格会在当前时刻显示一条横跨七天的红线。
- **根因**：当前时间线放在七个日期列的循环内部，并且没有使用 `isToday` 限制，导致每列都渲染一段相同位置的红线。
- **处理**：仅在今天列渲染当前时间线，并增加“现在”标签说明其含义。
- **状态**：**已解决**。

## 7. 测试缓存与开发环境问题

### DEV-001：`backend` 生成大量空 pytest 缓存目录

- **现象**：出现 47 个 `pytest-cache-files-*` 空目录及一个不可访问的 `.pytest_cache`。
- **根因**：`.pytest_cache` ACL/访问权限异常，pytest 缓存插件写入失败后反复使用兜底目录。
- **处理**：删除 48 个生成目录，并在 pytest 配置中禁用非必要的持久缓存插件。
- **验证**：重新运行测试后，零长度文件为 0、空缓存目录为 0、兜底目录为 0，且不再出现缓存权限警告。
- **状态**：**已解决**。

### DEV-002：仓库根目录仍有不可访问的 `.pytest_cache.bak`

- **现象**：`git status` 扫描时提示无法打开 `.pytest_cache.bak`。
- **影响**：不影响业务功能，但会制造 Git/工具噪声。
- **状态**：**环境问题，待清理**。

### DEV-003：测试依赖存在弃用警告

- **现象**：Starlette TestClient 提示旧 `httpx` 兼容层弃用；AnyIO 的 `BlockingPortal` 别名也已弃用。
- **影响**：当前测试仍通过，但未来升级依赖后可能失效。
- **状态**：**待处理，低优先级**。

### DEV-004：Windows 行尾警告较多

- **现象**：`git diff --check` 期间大量提示 LF 将被转换为 CRLF。
- **影响**：当前不构成 diff 错误，但会增加审查噪声并可能造成整文件行尾变更。
- **状态**：**待处理，低优先级**。
- **建议**：通过 `.gitattributes` 固定源码和 Markdown 的行尾策略。

### DEV-005：Next.js 构建出现 `--localstorage-file` 警告

- **现象**：静态页面生成期间 Node 提示参数未提供有效路径。
- **影响**：构建成功，目前未发现产品功能损坏。
- **状态**：**环境问题，待观察**。

## 8. 搜索、推荐与 AI 的已知缺口

### AI-001：CJK 长文本不适合只依赖现有词法检索

- **现象**：中文和日文简介难以通过当前简单 `LIKE`/FULLTEXT 方案获得稳定语义召回。
- **状态**：**待处理**。
- **规划**：动画优先建立本地 embedding/ANN 检索；模型不可用时降级到词法查询。

### AI-002：Staff、声优和关系数据尚未规范化

- **现象**：部分推荐逻辑仍从 JSON 元数据中查找，无法稳定表达人物、角色、职位和作品关系。
- **状态**：**待处理**；与 CAT-011 属于同一数据基础缺口。

### AI-003：全量书籍向量索引内存成本过高

- **现象**：动画加书籍按 1024 维 float32 粗略计算约 1.82 GB 原始矩阵，多 Web worker 复制会进一步放大内存。
- **状态**：**设计风险，待评测**。
- **规划**：第一阶段只索引动画；书籍考虑热门子集、内存映射或本地 ANN。

### AI-004：用户私人内容不能无条件发送给外部模型
